# Changelog

All notable changes to Olta are documented in this file.

## [1.0.0-Alpha] - 2026-08-08

### Added

- Established the Olta monorepo layout with the `olta-proxy`, `olta-campaign`, and `olta-feed` entry points under `cmd/`, and reusable implementation packages under `pkg/`.
- Added one embedded initial schema per supported campaign database at `pkg/campaign/migrations/{sqlite,mysql}/001_initial_olta_schema.sql`.
- Added schema-version tracking and final-schema validation for both fresh installs and compatible pre-Olta databases.
- Added native Ansible deployment roles that build and install Olta services from this repository.
- Added a uTLS-backed proxy transport with Chrome, Firefox, Safari, and per-connection Random browser profiles, including HTTP/2 and HTTP/1.1 ALPN negotiation.
- Added the in-memory campaign quishing service with configurable image size, foreground and background colors, and Low, Medium, or High error correction.
- Added recipient-specific `{{.QRCode}}` and `{{.RIdQR}}` email template tags and an authenticated `POST /api/quishing/preview` dashboard API.
- Added Phase 3 smart-cloaking middleware for the proxy gateway with lock-free in-memory IPv4/IPv6 CIDR and ASN matching for cloud providers and security crawlers.
- Added rule-based User-Agent, browser-header, and HTTP protocol inspection with configurable 302 redirect or 403/404 block enforcement before lure validation and session initialization.
- Added `-enable-cloaker`, `-cloaker-redirect-url`, `-cloaker-action`, `-cloaker-block-status`, and `-cloaker-trust-proxy-headers` options to `olta-proxy`.
- Added opt-in client-side environment verification with WebDriver/headless checks, WebGL software-renderer detection, and Canvas consistency assertions injected into proxied HTML responses.
- Added `-enable-js-inspect` and `-js-inspect-endpoint` options to `olta-proxy`, with configurable 302 safe-URL redirects or 403 enforcement for suspicious browser assertions.
- Added an opt-in asynchronous captured-session validation worker pool driven by proxy database capture events, with bounded queues, request timeouts, and non-sensitive identity metadata extraction.
- Added Discord, Slack, and generic JSON webhook telemetry for sanitized session validation results, configurable with `-enable-session-validator` and `-webhook-url`.
- Added randomized campaign delivery jitter with global `-min-send-delay` and `-max-send-delay` settings and optional per-campaign delay overrides.
- Added multi-variant campaign templates with deterministic round-robin recipient assignment, recipient-level persisted variant IDs, and variant-specific delivery, open, click, submission, captured-session, report, and error metrics in campaign API responses.
- Added campaign schema version 2 migrations for SQLite and MySQL, including automatic Variant A backfill for existing email campaigns and recipient results.
- Added embedded browser-in-the-browser campaign components with responsive simulated address bars, HTTP/HTTPS status indicators, draggable window chrome, and Windows 11, macOS, and Ubuntu/GNOME-style Linux themes.
- Added automatic client-platform theme selection plus explicit `{{.BITBFrame}}` and `{{.BITBFrameTheme}}` campaign template helpers.
- Added modular OAuth 2.0/OpenID Connect consent components with application and publisher branding, requested-scope presentation, redirect URI metadata, accept/cancel events, and the `{{.OAuthConsent}}` campaign template helper.
- Added single-binary CSS and JavaScript distribution for BITB and OAuth consent components through embedded campaign asset routes under `/static/components/`.
- Added a pure rule-based campaign personalizer with concurrency-safe nested spintax expansion that preserves Go template actions and ordinary HTML/CSS braces.
- Added a built-in scenario library with coherent subject, plaintext, and HTML variants for student/academia, general HR, finance/accounting, and IT/software engineering audiences.
- Added Turkish-normalized recipient routing across department, position, and role metadata, with `general_hr_scenarios` as the default fallback.
- Added rich personalization fields for `{{.FirstName}}`, `{{.LastName}}`, `{{.Position}}`, `{{.Department}}`, `{{.Company}}`, `{{.ManagerName}}`, and `{{.PhishingURL}}`.
- Added `-enable-spintax` and `-enable-role-routing` campaign options, both enabled by default.
- Added campaign schema version 3 migrations for SQLite and MySQL to persist recipient department, role, company, and manager metadata across targets, results, and test-email requests.
- Added an embedded multilingual campaign scenario library for English, Turkish, German, and Spanish across student, HR, finance, and IT categories, with locale and category fallbacks.
- Added runtime localized-template overrides through the `--custom-templates-dir` campaign option while preserving single-binary embedded defaults.
- Added periodic AWS, Google Cloud, Microsoft Azure, and Palo Alto public-range synchronization with concurrent feed ingestion and atomic, lock-free radix-trie publication.
- Added `-enable-ip-sync` and `-ip-sync-interval` proxy options, enabled by default with a 12-hour refresh interval.
- Added authenticated Spintax and BITB preview APIs plus a live campaign-template editor panel that renders five randomized message variations.
- Added Windows 11 light/dark, macOS light/dark, and Linux GNOME BITB preview themes with real-time dashboard switching.
- Added campaign schema version 4 migrations for SQLite and MySQL to persist recipient language metadata without altering the existing version 3 upgrade path.
- Added a shared `pkg/telemetry` event bus that tags every stage of the engagement kill chain — delivery, open, lure, cloak, verify, credential, capture, replay, and report — with its MITRE ATT&CK technique, outcome, and non-sensitive actor and campaign attributes, with a scalar-only, key-redacting `WithDetail` builder that keeps captured loot out of the stream by construction.
- Added campaign schema migration 006 (SQLite and MySQL) creating the `telemetry_events` table that stores the tagged event stream.
- Added four telemetry sinks: `campaigndb` (persists every event to the campaign database), `webhook` (Discord, Slack, and generic JSON dialects), `feed` (publishes a versioned `telemetry.v1` message to the Olta live feed), and `jsonl` (appends newline-delimited JSON to an owner-only, `0600`-mode file via the new `-telemetry-file` `olta-proxy` option), all fed from the same non-blocking bus.
- Added a per-campaign purple-team resilience report at `GET /api/campaigns/{id}/resilience`, computing kill-chain funnel targets, cloaker friction by network owner, and report-race timing from the telemetry stream, with unmeasured stages (cloak, verify, replay) reported distinctly from stages that were measured and saw nothing.
- Added an ATT&CK Navigator layer export at `GET /api/campaigns/{id}/resilience/navigator` (`domain: "enterprise-attack"`) that loads in Navigator without manual editing.
- Added a `telemetry` block to `olta-campaign`'s `config.json` (`cloaker`, `verify`, `session_validator`, all defaulting to `false`) that must be kept in sync with how `olta-proxy` was launched (`-enable-cloaker`, `-enable-js-inspect`, `-enable-session-validator`) so the resilience report's measured/unmeasured distinction stays accurate.
- Added a campaign-dashboard resilience panel that renders the kill-chain funnel, defensive friction, and report-race sections of `GET /api/campaigns/{id}/resilience`, with a one-click ATT&CK Navigator layer download, built through gulp as `static/js/dist/app/resilience.min.js`.
- Added a `StageInitialization` telemetry event emitted once by `olta-proxy` immediately before it serves, recording the configuration the process actually launched with (cloaker posture, verification, rate limiting, uTLS client profile, feed, IP sync, proxy-header trust, and version) so a report can show how the proxy was run. Secret-bearing flags are reduced to presence booleans or non-secret enums (`turnstile_enabled`, `webhook_configured`, `campaign_db_driver`) before an event is ever built, so the startup event can fan out to the webhook sink without posting the webhook's own URL or a MySQL DSN password back to itself.
- Added WebAuthn/passkey capability and ceremony observation to the injected browser-verification script: `window.PublicKeyCredential` presence, the asynchronously resolved `isUserVerifyingPlatformAuthenticatorAvailable()` and `isConditionalMediationAvailable()` values, and whether a `navigator.credentials` ceremony was initiated. The observation is measurement only — the wrapper always lets the original call and its return value pass through untouched — and is reported as a new `StageWebAuthn` telemetry stage that carries no ATT&CK technique, because a passkey defeating an AiTM proxy is the defender's control working, not adversary behavior.
- Added `PasskeyDefense` to the resilience report: `RanScriptTargets` (clients whose browser actually ran the injected script, the explicit denominator), `PlatformAuthenticatorAvailable`, `CeremonyInitiated`, and `PushedToWeakerFactor` as raw counts, never a percentage over a possibly trivial denominator. The measure reads `Measured: false` whenever browser verification was off, self-correcting to `true` only on actual `StageWebAuthn` events.
- Added `PasskeyDefense.Scope` and `PasskeyDefense.CorrelationReliable`, which carry the metric's IP-based correlation caveat into the JSON and dashboard rather than leaving it in a Go doc comment: `PushedToWeakerFactor` joins pre-lure WebAuthn observations to post-lure credential and capture events by client IP, so targets behind one corporate NAT egress can register as a single client. `CorrelationReliable` is `false` when the campaign's own rows show two or more distinct RIDs sharing an IP — direct evidence the join collided here, not a hypothetical — and `Scope` then names the collision explicitly.
- Added a live telemetry stream to the campaign results view at `GET /campaigns/{id}/feed`, behind the same session-cookie authentication as the neighbouring dashboard routes. A server-side `LiveFeedHub` subscribes to `olta-feed` as a viewer, holds a bounded 200-event ring buffer, reconnects with backoff, and fans events out to dashboard clients over Server-Sent Events — the browser never talks to `olta-feed` or sees its viewer token. With the feed disabled or unreachable the endpoint still answers normally with an empty, idle stream.
- Added operator tagging for captured sessions: `Tag`, `Notes`, and a constrained `SessionStatus` (`untriaged`, `triaged`, `high_value`, `replayed`, `discarded`) on campaign results, edited inline in the results table and written through `PUT /api/campaigns/{id}/results/{rid}/session`, which re-derives ownership from both the campaign and the fact that the RID belongs to it.
- Added campaign schema migration 007 (SQLite and MySQL) creating the `tag`, `notes`, and `session_status` columns on `results`, baked forward into the fresh-install schema so new and upgraded installs converge.
- Added `-g-driver` and `-g-tls-ca` options to `olta-proxy` so the proxy opens the campaign database through the same dialect factory the campaign service uses, rather than assuming SQLite.
- Added session identity rehydration to `olta-proxy`: the recipient ID is now persisted on the session record (encrypted at rest alongside username and landing URL) and the in-memory session maps are repopulated from the store at startup, so a proxy restarted mid-engagement still attributes a returning victim to their campaign recipient instead of capturing them unattributed.
- Added a phishlet `http_only` drift check: when a cookie auth token is captured, the value the phishlet declared is compared against the flag the origin's `Set-Cookie` actually set and a mismatch is logged with phishlet, token, domain, and both values. What is stored and exported remains exactly the observed flag — a fabricated one would behave differently when an operator re-imports the cookies to replay a session.
- Added a `-version` flag and a `feed.Version` constant to `olta-feed`, which previously had no way to report its version.
- Added a `SeenCapacity` setting to the session-validation worker, bounding the deduplication set to a fixed memory footprint over a long engagement.
- Added `Bus.Undelivered()`, counting events a bounded shutdown gave up on — distinct from `Dropped` (queue overflow, the bus is undersized) and `Failed` (a sink rejected or timed out, a sink is broken).

### Changed

- Renamed the Go module to `github.com/s4l1hs/olta` and migrated every internal import path.
- Updated build scripts, service definitions, runtime messages, and asset resolution for the three Olta binaries.
- Enabled SQLite WAL mode, busy timeouts, foreign-key enforcement, and bounded connection usage to improve concurrent campaign access.
- Consolidated inherited campaign migration histories into the unified Olta v1 schema; fresh databases no longer replay redundant historical migrations.
- Updated deployment recipes to target `olta-campaign` and `olta-proxy` rather than downloading upstream binaries.
- Replaced non-releasable worker tickers and added graceful `SIGTERM` handling for service-managed campaign shutdowns.
- Updated the email worker shutdown path to cancel active jitter waits, wait for dispatch goroutines, and unlock persisted mail logs for clean campaign resumption.
- Added the `-client-profile` proxy option and routed outbound HTTP traffic through the browser-profiled transport while preserving upstream proxy support and standard timeout errors.
- Replaced the fixed QR helper with an in-memory generator that returns Base64 PNG, data URI, and inline MIME attachment data without temporary filesystem writes.
- Refreshed the Olta logo, architecture diagram, and README screenshots to remove legacy EvilGophish branding.
- Extended recipient persistence and CSV import with language metadata so localized templates follow each target through campaign delivery.
- Added a reported continuity fallback for Palo Alto's last published official scanner ranges when its documentation endpoint returns a client-rendered shell, preventing one unavailable feed from blocking otherwise complete atomic refreshes.
- Treated the standard HTTP server-closed signal as a successful campaign shutdown so admin and phishing processes exit cleanly during service stops.
- Routed the `campaigndb` telemetry sink through `campaignstore`'s existing single-writer queue instead of opening a second, uncapped connection to the same database, and reordered proxy shutdown so the bus drains into that queue before the store closes its handle.
- Fanned each event's per-sink deliveries out concurrently rather than sequentially, so one event costs the slowest sink rather than the sum of every sink's timeout. Events are still processed one at a time in queue order, so per-sink ordering is unchanged.
- Cached macro-expanded `sub_filter` regexes on the proxy rather than recompiling every pattern for every enabled phishlet on every proxied response, cutting the apply path from 37 to 14 allocations per call. A pattern that fails to compile is never cached, so the caller's existing fallthrough is unchanged.
- Bounded intercepted response bodies to a 10 MiB read. A larger body is never truncated — the client receives the original bytes through a multi-reader — but no rewrite pass runs against it and only the capped prefix is ever buffered. Binary MIME types that can never carry a rewrite target now skip the per-phishlet rewrite loop entirely, driven by an explicit allow-list so a text-based type like `image/svg+xml` is not misclassified.
- Reconciled response framing (`Content-Length`, and stale `ETag`, `Content-MD5`, and `Transfer-Encoding`) whenever a body's length actually changed, rather than only when the verification script was injected — `sub_filter` rewriting, auto-filter URL patching, dot de-obfuscation, and the OpenGraph/session injections previously left a stale `Content-Length` in place. An unmodified response is left byte-for-byte untouched.
- Extracted the proxy's response-modification steps out of the goproxy closures into free functions behind a test seam, so header rewriting, cookie normalization, `Location` rewriting, and sub-filter application can be exercised without a live MITM listener. Control flow is unchanged.
- Removed the inert `cmd/olta-proxy/vendor` directory: Go honors a vendor tree only at the module root, so all 1,456 files were ignored by the toolchain while costing 30 MB, most of the repository's gofmt noise, and a large tree of stale third-party code for CVE scanners to flag.
- Stopped tracking prebuilt binaries and a release tarball under `build/`, which is now ignored; releases are built from source and published as GitHub release artifacts with checksums.
- Pinned `golang.org/x/crypto` to v0.33.0 and `golang.org/x/net` to v0.35.0 — the newest releases on each line that preserve the documented Go 1.22 floor — and moved `github.com/mattn/go-sqlite3` off the mis-tagged `v2.0.3+incompatible` onto the maintained v1.14 line.
- Aligned all three binaries on the single version string `1.0.0-Alpha`, replacing the inherited Gophish `0.12.0` and evilginx3 `3.2.0` values.
- Rewrote `README.md` to document the telemetry bus, the resilience report, and the evasion and social-engineering capabilities shipped since the pre-telemetry version, and added a Releases section describing how binaries are built and published.
- Corrected the telemetry design spec's claim that `Event.ID` is a ULID: it is a 128-bit `crypto/rand` value hex-encoded to 32 characters, chosen to avoid a module dependency for time-sortability the indexed timestamp column already provides.
- Removed the session-validation worker's unreachable dispatch error path; `Close()` no longer returns an error, since nothing on the shutdown path performs I/O and per-job failures already reach the caller through `OnResult`.

### Fixed

- Guarded the proxy's session maps with the `session_mtx` that already existed for the purpose but was never locked: the goproxy request handler mutated them from a per-connection goroutine, so two victims landing at the same instant could trigger Go's unrecoverable "concurrent map writes" fatal error and kill the process, dropping every in-flight session.
- Stopped setting a branded `X-Olta-Original-Host` header on every request forwarded to the target's real servers. Nothing read it back, so its only effect was writing this tool's name into the victim organization's web server, WAF, and SIEM logs — which defeats the purpose of a proxy meant to be indistinguishable from the genuine site.
- Resolved the proxy's client IP through the cloaker's own resolver, which uses `RemoteAddr` unless proxy-header trust is explicitly enabled, instead of unconditionally trusting six client-controlled headers. Previously any client could bypass rate limiting and blacklisting by rotating a header, and under `blacklist_mode=all` could poison the persistent blacklist with an arbitrary chosen address — including the operator's own infrastructure — across restarts. The existing `-cloaker-trust-proxy-headers` flag now governs the core proxy's rate limiter, blacklist, and persisted remote address as well.
- Stopped recording `127.0.0.1` as the actor IP on every campaign-side telemetry event. The real client address was already carried on the session; when no address is known the field is now simply absent rather than fabricated, and the persisted result IP is no longer overwritten with a loopback placeholder.
- Fixed the dashboard's captured-session cookie export, which serialized capitalized Go field names and so could not be imported into Cookie-Editor or EditThisCookie at all. It now emits the lowercase keys those tools require, matching the terminal export field for field, including the `secure` flag inferred from `__Host-`/`__Secure-` name prefixes. `sameSite` is deliberately still omitted: the token record holds no genuine value for it.
- Fixed `campaignstore` hardcoding the `sqlite3` dialect: on a MySQL-backed deployment `olta-campaign` opened its configured database while `olta-proxy` silently kept trying to open a SQLite file, losing proxy-side events — the entire capture half of the kill-chain funnel — with no configuration validation catching it.
- Bounded the session-validation worker's deduplication set with a fixed-capacity FIFO. Every distinct session ID the worker had ever accepted previously stayed in the map for the process lifetime, so a worker running for the length of an engagement — the scenario it exists for — grew without bound.
- Scoped unattributed cloak and verify events to the campaign's active window in the resilience report. Because those stages fire before lure validation establishes a recipient, they carry no campaign ID, and `Compute` previously merged every such event ever recorded on the install into whichever campaign asked for a report. The report now states plainly, through `UnattributedScoped` and `FrictionScope`, that a time window narrows but cannot fully separate concurrent campaigns on one install.
- Aggregated the ATT&CK Navigator export by technique ID. Delivery, open, and lure all map to `T1566.002`, and Navigator applies a layer's entries sequentially, so only the last entry for a shared technique survived on screen — delivery and open were present in the JSON but invisible the moment Navigator loaded it. Each technique now gets one entry scored by its maximum stage count, with a comment naming every contributing stage and count.
- Fixed three resilience-panel rendering gaps: the friction scope caption is now rendered on every code path, the race summary shows the delivered denominator its three buckets sum to, and a genuine zero-second median time-to-report is no longer rendered as "n/a" alongside a truly absent one.
- Bounded total telemetry bus shutdown time. `Close()` previously waited for the drain to walk the whole queue with every sink call bounded only by the 10-second per-sink timeout, so with the production defaults and every sink wedged the worst case was roughly 11 hours — a hang with a deadline, not a graceful shutdown. Close now races the drain against a 30-second deadline and, on expiry, signals the drain to stop calling sinks and count what is left, terminating promptly instead of hammering a wedged sink.
- Fixed the parsing of the phishlet `http_only` auth-token modifier, which was silently accepted and had no effect, leaving the flag hardcoded to `false`.
- Fixed `Phishlet.Clear()` leaving `js_inject` and `intercept` append-only across reloads and never resetting login, landing path, redirect URL, version, path, or the username/password field bindings — so reloading a phishlet duplicated injections and a failed reload left stale routing state from the previous load in place.
- Exempted the live-feed route from the admin server's blanket gzip middleware, which buffers small writes and defers `WriteHeader` until it can decide whether to compress, silently withholding an SSE response — headers included — on a quiet connection.
- Stopped the campaign results poll from clobbering an in-progress session edit. The poll rebuilds the table wholesale, destroying row markup, so a tag input removed mid-edit was never blurred, its save handler never fired, and whatever the operator had typed was silently lost. The refresh now skips a cycle while an edit holds focus or an unsaved note is dirty, bounded to five consecutive cycles so a half-typed note left behind cannot freeze the table for the rest of the engagement.
- Clamped the proxy banner's version padding to a minimum of one space; with an eleven-character version string the previous expression went negative and panicked.
- Built every dashboard app script through gulp. `personalizer_preview.js` was absent from the build and loaded from the unminified source path in production, `qr_code.js` and `sms_campaigns.js` shipped stale hand-committed bundles a real build would never refresh, and a dangling glob for a file that has never existed in this repository made `gulp scripts` fail outright.
